# Подмена адресов для Мобильного клиента 1С

`proxy4_MobileClien1C` — утилита, которая при запуске отладки Мобильного клиента 1С из
Конфигуратора подменяет в передаваемых на устройство параметрах имя компьютера на IP-адрес.

## Назначение

При запуске отладки мобильного приложения из Конфигуратора 1С адрес публикации базы и адрес
сервера отладки передаются на мобильное устройство с именем компьютера, на котором запущен
Конфигуратор. Когда отладка выполняется в виртуальной машине, обратиться к родительскому ПК
по имени, как правило, невозможно — отладка не подключается. Утилита исправляет адрес
публикации базы и адрес сервера отладки 1С в момент начала отладки из Конфигуратора.
Это существенно облегчает процесс разработки Мобильного клиента 1С.

Утилита не изменяет Конфигуратор 1С, мобильное приложение и эмулятор, не требует root-прав
на устройстве и не требует ручных действий во время запуска отладки.

## Как работает

```
adb-клиенты (Конфигуратор 1С, эмулятор, консольный adb) ──▶ 127.0.0.1:5037 (прокси)
                                                              │
                                       перехват только shell-команд вида
                                       am broadcast ... com.e1c.mobile.* ...
                                       /DEBUGGERURL... /WS ...
                                       имя этого ПК -> IP (vm / pc / manual)
                                                              ▼
                                                        127.0.0.1:5038 (настоящий adb-сервер)
                                                              ▼
                                                        устройство / эмулятор
```

- В команде распознается запуск мобильного клиента 1С по признакам `com.e1c.mobile.`
  и ключам `/DEBUGGERURL` / `/WS` — без привязки к имени конкретного компьютера.
- `/DEBUGGERURL` и `/WS` обрабатываются независимо: адреса могут различаться.
- Хост заменяется только если он совпадает с именем текущего компьютера.
  Если в адресе уже указан IP или имя другого компьютера — адрес не меняется.
- Вся остальная работа adb (установка приложения, `push`/`pull`, `logcat` и т.д.)
  проходит прозрачно, без вмешательства.

## Требования

- Windows 10/11
- .NET Framework 4.x (входит в Windows, компилятор `csc.exe` — там же)

## Сборка

```
tools\build.cmd
```

Результат сборки — `bin\proxy4_MobileClien1C.exe`.

## Запуск

1. При первом запуске рядом с `bin\proxy4_MobileClien1C.exe` создается `bin\proxy4_MobileClien1C.ini`
   (шаблон — `bin\proxy4_MobileClien1C.ini.default`).
2. запустите `bin\proxy4_MobileClien1C.exe` вручную после старта ПК.
   Прокси работает до остановки или перезагрузки ПК.

Если на порту 5037 уже работает adb-сервер (например, его поднял эмулятор), прокси
автоматически перенесет его на порт 5038, запомнит подключенные устройства и переподключит
их. Если порт занят не adb-процессом — прокси завершится с кодом 2 и диагностикой в логе,
ничего не завершая принудительно.

## Остановка

- закрыть консольное окно, или
- Ctrl+C в консоли, или
- `bin\proxy4_MobileClien1C.exe stop`

При остановке adb-сервер возвращается на порт 5037, устройства переподключаются.

## Конфигурация (proxy4_MobileClien1C.ini)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `mode` | `pc` | Режим подстановки IP: `vm` = 10.0.2.2 (стандартный адрес хоста для виртуальных машин с NAT); `pc` = текущий IPv4 этого ПК (определяется в момент команды, виртуальные адаптеры исключаются); `manual` = значение `manual_ip` |
| `manual_ip` | пусто | IP-адрес для режима `manual` |
| `adb_path` | пусто | Путь к `adb.exe`, если его нет в текущем каталоге или рядом с exe. Порядок поиска: текущий каталог → каталог exe → `adb_path` |
| `listen_port` | 5037 | Порт прокси (стандартный порт adb-клиентов) |
| `backend_port` | 5038 | Порт настоящего adb-сервера |
| `log_file` | proxy4_MobileClien1C.log | Файл лога (рядом с exe) |

## Лог

Каждая подмена фиксируется строкой:

```
2026-01-01 12:00:00.000 REWRITE 'PC-NAME' -> '192.168.1.10' (mode=pc)
```

Пропуск замены (в адресе IP или чужое имя): `REWRITE-SKIP ...`.

## Диагностика

| Симптом | Причина / действие |
|---|---|
| `port 5037 is occupied by a non-adb process` | Порт 5037 занят не adb — освободите порт |
| `adb backend is not available` | Не найден `adb.exe` (текущий каталог / каталог exe / `adb_path`) и ни один сервер не отвечает на 5038 |
| `REWRITE-SKIP reason=no-ip-resolved` | Режим `pc`/`manual` не смог определить IP (нет подходящего адаптера или пустой `manual_ip`) |
| Прокси упал | Порт 5037 освобождается, adb-клиенты поднимают свой сервер — работа продолжается без подмены; перезапустите `bin\proxy4_MobileClien1C.exe` |

## Самопроверка

```
bin\proxy4_MobileClien1C.exe selftest            :: все тесты
bin\proxy4_MobileClien1C.exe selftest <фильтр>   :: подмножество по подстроке имени теста
```

Тесты герметичны и не влияют на работающий прокси.

| `tools/` | `build.cmd` — сборка проекта |
| `docs/` | План реализации (исторический документ) |
| `README.md`, `LICENSE` | Описание и лицензия |
